# Agent 工作指南

[文档目录](README.md) · [仓库入口](../AGENTS.md) · [技能目录](../.agents/skills/README.md)

目标是尽快完成用户要求，并保留足以证明结果的检查。不是减少有用的测试，而是
减少重复读取、无关准备、重复构建和没有新信息的确认。

## 一次确定范围

确认分支、基准提交、工作区修改和交付目标，然后读取相关代码、调用方及匹配技能。
能从仓库或已连接工具查到的事实，不再问用户。只有任务涉及某个 PR、分支历史或
部署状态时才调查它们。小改动直接实施；跨模块或高风险任务使用简短计划，不为
每次修订新建计划、审计记录或进度文档。

已有明确授权时继续完成对应操作。扩大到未授权的合并、发布、生产变更或付费操作，
以及金额或目标发生变化时，才需要新的授权。工具自身的权限与确认流程仍然有效。

## 选择验证

以下是起点，不是每次必须全部执行的清单。命令以当前
[justfile](../justfile) 和 [前端脚本](../apps/web/package.json) 为准。

| 改动 | 首选检查 | 何时扩大 |
| --- | --- | --- |
| 文档、AGENTS.md、技能正文 | `python3 -B scripts/check-docs-brand.py --docs-only`，审查差异与改动的示例 | 改检查器才运行其单元测试；改命令则核对实现或在隔离环境验证 |
| 现有翻译值 | 翻译工具校验、逐语言差异、实际受影响的显示 | 改调用方或类型才增加类型检查；新增交互才增加对应 UI 测试 |
| React/TypeScript | 受影响测试、改动文件的格式与 lint、`just typecheck-web` | 导入、构建配置、依赖或加载方式变化时运行 `just build-web` |
| Go | 受影响包和直接调用方的测试；改动文件的格式检查 | 公共接口、模块依赖或影响范围不明时运行 `just test-go` 及相关静态检查 |
| Rust | 受影响 crate 的测试及格式检查 | 共享接口变化时运行 `just test-rust` 及相关静态检查；不顺带测试 Web/Go |
| 部署入口或发布脚本 | `just test-deploy-entrypoint` 及受影响的原生部署测试 | 安装、状态机、恢复或数据库逻辑变化时验证相应故障路径 |
| Logo | `python3 -B scripts/check-docs-brand.py` 与实际显示 | 组件实现变化时增加对应前端检查 |
| 广泛影响 Go/Web 的改动 | `just check` | 需要验证产物时再构建相应组件；Rust 只在受影响时加入 |

`just check` 已包含格式、lint、前端类型检查、Go/Web 测试和部署入口检查。
不要在它前后再次运行相同检查。`just build-web` 已包含构建和 bundle 检查。
不要用全仓格式化处理局部改动。

鉴权、计费、余额、持久化和迁移的改动，需要证明相关权限、失败、重试、并发与
数据一致性行为。优先运行能复现问题的测试和相邻回归测试；它们失败时修复原因，
不能为了提速删掉断言、忽略失败或把无关命令包装成测试证据。

文档检查器只覆盖维护入口、项目技能的本地路径/元数据和 README 徽章。它不覆盖
所有 Markdown、完整 YAML、远程链接、标题锚点或命令行为。其他改动文档的链接和
示例也需审查，不得将这个检查描述为全仓验收。

仅当相应工具代码变化时运行其自测：

```bash
python3 -B -m unittest discover -s scripts -p test_check_docs_brand.py
node --test .agents/skills/i18n-translate/scripts/apply-translations.test.mjs
```

## 复用结果，不重复执行

同一任务中，已读文件没有相关变化就不重读。检查结果可以复用，但必须保留实际
测试源码、命令、退出状态，以及影响结果的依赖、配置和环境。相关输入变化，才
重跑受影响的检查。不能把旧提交的测试说成在新提交上执行过。

发布按 `scripts/local-release-tests.py` 绑定的组件 Git 对象验证证据。已有记录
匹配时直接复用；导入结果须有实际命令、退出码和原始日志。打包或工作流变化也可能
使记录失效。不要手改哈希绕过验证，也不要仅因无关合并就重建未变化的应用。
具体操作见 [部署流程](deployment-workflow.md)。

独立的读取和检查可以并行。共享写入、同一构建目录、数据库迁移和生产切换不可
盲目并行。小内存机器避免同时启动多个重型构建。不要为一个小任务强制创建多个
Agent，或把几秒的工作拆成多轮交接。

## 遇到失败与结束任务

失败后先区分源码、依赖、网络和权限问题。只对适合重试的读取进行有限重试；相同
原因再次失败就换用现有可行路径或报告具体缺项。不要因下载或状态读取失败重跑
成功的构建。写请求结果不确定时先查准确 ID，不能重复发布、迁移或付款。

交付前审查差异，报告修改、实际检查、未验证项和提交/PR。用户目标完成且相关
检查通过后结束，不自行追加重构、全站审计、发版或部署。生产是否变更单独说明。

## 维护技能

每个技能只负责一个工作，描述先写触发条件，再写不适用范围。正文保留必要输入、
执行路径与完成条件。大段背景和特殊恢复步骤放到按需读取的参考资料；通用规则
只在本指南维护。上游参考与署名保留，不复制第二个可发现的技能入口。

新增规则应解决已经观察到的重复错误。不要把单次事故变成所有任务的永久前置步骤。
技能修改后检查元数据、链接和适用范围，并用代表性请求审查是否误触发。
